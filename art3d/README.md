# art3d：单位资料与图像（3D 化参考）

2026-11-01 从游戏目录的 `tc.dat` / `tc2.dat` 实测导出，配合 `server/units_manual.json`、`server/unitnames.py`、`server/aliens.py`。
用途：Blender 建模参考、three.js 资源规划。图像只作造型参考，不作贴图。

## 内容

| 路径 | 说明 |
| --- | --- |
| `units.json` | 索引：95 个美术码，每个的种类、底盘名、中文名、框架、兵科、各动作的方向数 / 每方向帧数 / 总帧数 |
| `contact_sheet.png` | 全部单位一览（方向 0 的站立图） |
| `units/<美术码>/info.json` | 该美术码的完整资料：所有底盘与 Mk 的手册数值、每个精灵层的画布、枢轴点、方向、帧数、枪口点 |
| `units/<美术码>/sheets/<档名>.png` | 每个精灵档一张总表：一列（row）= 一个方向，一栏（column）= 一帧；格子已裁到所有帧的联集，`info.json` 的 `sheet_crop`、`cell`、`pivot_in_cell` 可换算回原画布 |
| `units/<美术码>/views/dirNN.png` | 站立图第 0 帧的各方向单张（建模三视图用） |
| `units/<美术码>/turnaround.png` | 各方向并排，×4 最近邻放大 |
| `units/<美术码>/picture.jpg`、`pictures.jpg` | dat 内的单位插图（276×344）与小图（80×100），56 个美术码有；比战场精灵清楚，是最好的造型参考 |
| `xpfx.py` | 加强版 .xpf 解码（遮罩层、枪口点、偏移表结尾、方向判断） |
| `export_units.py` | 重新导出：`python3 art3d/export_units.py "<游戏目录>"`；已完成的美术码会跳过，可用 `ART3D_BUDGET=秒数` 分段跑 |

## 实测结果

- 95 个美术码：地面 g 58、空中 a 25、英雄 h 11（指挥官外观 1–11）、其他 d 1；其中 5 个手册与伺服器都没用到：a003、a025、d001、g007、g053。
- 战场精灵画布约 100–175 px，单位本体约 30×45 px。
- **帧的排列**：帧按「帧序优先」存放，帧索引 = 帧号 × 方向数 + 方向号。
- **方向数**：站立与移动大多 8 方向（约八成），其余 16 方向；攻击层 8 方向与 16 方向约各一半；少数 32 方向。
- **方向定义**：方向 0 朝画面右方，索引在画面上顺时针增加（D/4 朝下、D/2 朝左、3D/4 朝上）。以 Behemoth、Chimera、Imp、Daeva、Wraith、Shade、Mephit、Spirit 攻击帧的枪口点，以及左右镜像对验证。
- 死亡 `da` 通常只有 1 帧（残骸）。
- 13 个精灵层的方向无法自动判断（`dirs: null`）：a012、a019 全部，g002 / g004 / g041 的 `sg`，g029、g049、g057 的 `at`，g054 的 `st` / `mo`。总表先排成一列，需要人工目视。
- 自动判断置信度低的层在 `info.json` 标 `layout_confident: false`，并附 `mirror_check` 分数。

## .xpf 格式补充（相对 tools/xpf.py）

- 类型字段只看低 8 位。
- `type & 0x10`：遮罩层（影子、脚印），游程不带像素资料。
- `type & 0x04`：每帧开头是枪口点：u8 个数，再接个数 ×（u16 x, u16 y），座标是精灵画布像素。攻击层 `at` 与部署层 `sg` 有。
- 偏移表从第 14 字节开始，到等于档案大小的那一项结束；标头的 rows 字节只是上限（rows × 24 + 1）。

## 层与动作代码

| 代码 | 意义 |
| --- | --- |
| st / mo / at / da | 站立 / 移动 / 攻击 / 死亡残骸（已确认） |
| sg | 部署或攻城状态（推测） |
| em | 英雄动作（推测） |
| dt、db、heh、hel、sa、sk、sf、m、pri 等 | 未确认 |
| 后缀 s | 影子（遮罩） |
| 后缀 p | 脚印 |
| 后缀 b | 第二颜色层（用途未确认） |
| 后缀 d | 发光或特效层（类型带 0x08，用途未确认） |
| 后缀 c、l | 未确认 |
