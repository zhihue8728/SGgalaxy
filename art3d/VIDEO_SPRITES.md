# AI 视频 → 单位帧动画（2026-11-03）

使用者：整理单位需要的视角，生成提示词让豆包做各方向的移动影片，再转成帧动画。
工具：`tools/video_to_frames.py`（视频 → 帧）、`tools/hd_pack.py --from-render`（帧 → HD 图集）。

## 游戏需要的视角（实测 g039 渲染设定，所有单位相同）
- 镜头：**正交投影**（没有透视），从斜上方 **俯视 55°**（离地平线 55°，离垂直 35°），镜头永远不动。
- 光：主光从画面左上方来，影子落在单位右侧偏后方。
- 方向：8 个（部分单位 16 个），**0 = 面朝画面右方，顺时针**：

| 方向 | 单位面朝 | 跑向 |
|---|---|---|
| d0 | 画面右方（侧面） | → |
| d1 | 右下方（斜前方，看得到正面和右侧） | ↘ |
| d2 | 正下方，面向镜头 | ↓ |
| d3 | 左下方 | ↙ |
| d4 | 画面左方（侧面） | ← |
| d5 | 左上方（斜背面） | ↖ |
| d6 | 正上方，背对镜头 | ↑ |
| d7 | 右上方（斜背面） | ↗ |

- 帧：移动 12 帧一个循环（一个完整步伐：左右脚各一步），首尾相接。站立 12、攻击 14、死亡 1。
- 位置：单位的地面中心（枢轴）固定，所以视频里要**原地跑步**（像在跑步机上），人不能离开画面中央。
- 大小：首帧参考图 1024×1024，单位已经按游戏比例放好；视频保持这个构图，不要推近或拉远。

## 每个方向的首帧参考图
`art3d/units/<码>/video/ref/<码>_dN.png`：现有渲染（或原版精灵放大）贴在纯绿底（#00B140），渲染画布 ×2.6，枢轴在 (512, 700)。
豆包用「图生视频」，**首帧上传这张图**，这样外观、颜色、方向、比例都跟游戏一致。

## 提示词
见 `art3d/units/<码>/video/prompts.txt`（每个方向一段，复制贴上即可）。共通要求：镜头固定、原地跑、纯绿背景、不加特效和阴影、不改外观。

## 转换
视频命名 `<码>_dN.mp4` 放进 `art3d/units/<码>/video/`，然后：
```
python tools/video_to_frames.py OUT <码> mo art3d/units/<码>/video
python tools/hd_pack.py client/sgrender/hd --from-render OUT <码>
```
video_to_frames：去绿底 → 用首帧对齐参考图得到缩放与枢轴 → 去掉镜头漂移 → 自动找一个完整步伐的循环 → 重新取样成 12 帧 → 输出渲染画布帧 + 投影影子。
自测：用渲染帧合成的视频（加漂移、缩到 720p）转回来，与原帧轮廓重叠率 0.96–0.98，缩放、循环长度、漂移都正确。

## 已知限制
- 光剑等发光部分没有单独的发光层（视频里直接画在身上）；之后可用颜色把剑抠出来，套 hd_pack 的光剑特效。
- 视频质量取决于 AI：方向转错、滑步、手脚变形、光剑换手都会直接进游戏，要先看预览再发布。
- 每个方向各生成一次，8 个方向细节可能略有差异。
