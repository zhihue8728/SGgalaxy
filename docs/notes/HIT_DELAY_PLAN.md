# 方案 A：延遲扣血（先看到攻擊動畫，再扣血）— 規劃（2026-10-20）

## 現況（反組譯確認）
- 普通攻擊 004e55b0：冷卻一到，同一 tick 內「切換開火動作(狀態4) + 直接扣血 004cb3d0 + 在目標處產生命中特效」，
  狀態4持續半個冷卻後轉狀態5。沒有彈道時間；第一發在進入射程當下立即擊發（上次開火時間=0）。
- 扣血的呼叫點（004cb3d0）：普通攻擊 004e55b0（主目標 + 火焰噴射器的範圍傷害）、對空/特殊攻擊 004e8890、004e8c60、
  004e5090、投射物 00496650/00496920/00496bb0、手榴彈 004e6190、地震 004e6cf0、自爆 004d8c10、IRBM 落地 004d78c0、
  延遲事件 0x36 004d75c0 等。
- 客戶端本來就有「延遲事件」機制：每個單位一條依 tick 排序的事件佇列（推入 005c1310，例：005c1e80 推入事件 0x36
  [時間][目標]），由 004c5a70 在到達 tick 時分派（switch，0x00–0x4x）。所有客戶端以相同 tick 執行 → 具決定性、可回溯。

## 設計
1. 新事件類型 0x60「延遲命中」，參數 [目標 uid][傷害][特效/類型]。
2. 開火當下：保留開火動作與冷卻計時（DPS 不變），**不扣血、不產生命中特效**，改為推入事件 0x60，時間 = 現在 + D。
3. 事件到時：目標仍存活 → 呼叫 004cb3d0 扣血 + 產生原本的命中特效；目標已死 → 略過。
   （射擊者在 D 期間死亡：子彈已射出，照樣命中。）
4. D 的取值：先用 D = min(冷卻/2, 40 tick)，即命中落在開火動作的後段；之後依實際動畫逐武器微調（表格放在補丁資料區）。
5. 技能同樣處理：手榴彈、地震、EMP、核融合等改為「動作開始 → D 後結算」。IRBM、核融合原本就有延遲事件，維持。

## 實作步驟
1. 補丁工具 tools/patch_sg.py：複製 SG.exe → SG_hitdelay.exe，新增一個 PE 區段放新程式碼與 D 表。
2. Hook 點：
   - 004e55b0 等開火函式：把「扣血 + 命中特效」那段改成 jmp 到新程式碼（推入事件 0x60），返回原流程。
   - 004c5a70 事件分派：在 switch 前判斷 type==0x60 → 新的處理函式（扣血 + 特效），其他類型照舊。
   - 新的事件推入函式：仿 005c1e80 的寫法（建立事件物件、填類型與參數、呼叫 005c1310）。
3. 版本識別：補丁版客戶端握手送不同版本值；伺服器 REQUIRE_HIT_DELAY_CLIENT=True 時拒絕未打補丁的客戶端
   （同一場戰鬥的客戶端必須是同一套規則，否則模擬會分歧）。
4. 伺服器端：死亡已由控制方客戶端回報（ALIEN_CLIENT_CONTROL），不需改；伺服器的傷害記錄（擊殺歸屬、日誌）
   與技能結算時間一併加上 D。

## 驗證
- 離線：反組譯補丁後的 SG_hitdelay.exe，確認跳轉、堆疊平衡、暫存器保存。
- 遊戲內：近戰/遠程/對空、火焰範圍、手榴彈、連點、目標在 D 內死亡、射擊者在 D 內死亡、打到 0 血時的死亡時間。
- 多人：兩個客戶端同場，雙方看到的血量與死亡時間一致。

## 風險
- 要所有玩家都用補丁版客戶端；未打補丁的會與他人模擬不同步。
- 事件佇列有回溯/清除機制（005bf550），新事件必須遵守相同的時間規則。
- 部分開火函式可能內聯了多處扣血，需逐一處理；漏掉的武器仍是立即扣血（可接受，逐步補）。

## 預估
反組譯與補丁約 2–3 輪；先做普通攻擊（004e55b0）驗證整套機制，再擴展到其他武器與技能。
